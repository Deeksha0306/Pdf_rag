# PRD — PDF RAG System

## Overview

A lightweight, locally-run tool that lets users upload a PDF document and ask natural language questions about its contents. Answers are generated by Claude using only the content of the uploaded document.

**Target users:** Developers, researchers, and analysts who need to quickly query long PDFs without manually reading them.

---

## Problem Statement

Reading and extracting specific information from long PDF documents (reports, papers, manuals) is time-consuming. Users need a way to ask direct questions and get accurate, sourced answers without leaving their local environment or sending documents to a third-party SaaS tool.

---

## Goals

- Allow users to upload any text-based PDF and ask questions about it
- Return accurate answers grounded strictly in the document's content
- Show which parts of the document were used to generate each answer
- Run entirely on localhost — no cloud storage, no data persistence
- Keep setup simple: one command to install, one command to run

## Non-Goals

- No user authentication or multi-user support
- No persistent storage of documents or chat history across sessions
- No support for scanned/image-only PDFs (requires OCR, out of scope)
- No production deployment or public hosting
- No support for multiple documents simultaneously

---

## User Stories

| # | As a… | I want to… | So that… |
|---|-------|-----------|----------|
| 1 | User | Upload a PDF via drag-and-drop or file picker | I can quickly load the document I want to query |
| 2 | User | See confirmation that the document was indexed | I know it's ready before I start asking questions |
| 3 | User | Type a question in natural language | I get an answer without writing code or queries |
| 4 | User | See which chunks of the document were used | I can verify the answer against the source |
| 5 | User | Ask multiple follow-up questions | I can explore the document conversationally |
| 6 | User | Clear the document and load a new one | I can switch between PDFs in the same session |

---

## Success Metrics

- Document indexes in under 30 seconds for a 100-page PDF
- Answers are factually grounded in the retrieved chunks (no hallucination beyond the context)
- Setup takes under 5 minutes from clone to running

---

## Constraints

- API key must never be stored in source code — loaded from `.env`
- All document processing happens server-side in Python
- No external database — embeddings stored in memory per session
- UI must work in a standard browser with no JavaScript framework dependencies
